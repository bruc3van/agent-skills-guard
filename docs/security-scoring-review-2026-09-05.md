范围：当前 v1.3.6 未提交工作区。此次在此前安装/卸载、跨技能归属和评分修复之上继续改进，未提交、未发布。没有改写正常技能内容、添加技能白名单或统一抬高分数。

## 确认问题与修复

| 问题 | 证据与处理 |
| --- | --- |
| Python eval 同时误报、漏报 | 原表达式命中 run_eval / literal_eval，漏掉 value = eval(input)。改为独立 eval 或 builtins.eval 调用；排除 model.eval、普通函数名和整行 Python 注释。eval 的动态输入是否可信仍需要人工判断，单独调用保持 Low。 |
| 可执行脚本因目录名豁免 | docs/run.py、examples/run.py 被 skip_in_docs 移除；pipeline 也跳过文档目录脚本。改为只有文本文档获得文档降级，脚本不因目录名降级。 |
| README 扫描覆盖缺口 | 安装准备、确认和已安装重扫此前显式跳过 README。现纳入默认应用扫描入口，补充 README 中 curl 管道命令检出；普通说明文字负例不扣分。显式调用 ScanOptions.skip_readme 的能力保留。 |
| shell 续行改变命令词 | r\\换行m 被扫描成 r m。按续行语义连接命令词并保留起始行号。没有使用 NFKC 或剥零宽字符来改写命令含义。 |
| 跨行规则选路与位置错误 | 含 [^\r\n] 的规则被误当跨行规则；首个命中被排除时，后续命中被漏掉；行号偏移。区分字符类，遍历所有跨行命中，逐命中排除并修正行号。 |
| 下载和无关执行被关联 | 下载 data.json 后运行 build.py 曾触发下载执行链；URL 在前、-o 在后则可能漏报。使用 shell 参数解析，关联输出目标与执行目标，支持引号、长选项及明确的 base64 解码到另一目标的链路。 |
| 不参与评分的策略丢失 | Auditability-only 策略报告为 100，序列化后重算变为 98。扫描时保存策略处理后的有效权重，跨技能刷新和数据库重读保持一致。 |
| 分析器未统一遵守策略 | 同形字等分析器结果不遵守禁用/严重度/硬触发覆盖。统一在进入报告前应用策略，回归验证显式阻断开关。扫描覆盖缺失状态仍独立保留。 |
| 策略指纹不稳定 | HashSet 无序序列化使相同策略产生不同指纹。只排序集合字段，保持覆盖列表顺序。测试反复反序列化后指纹一致。 |
| Python 字节码被当惰性资源 | .pyc / .pyo 不再直接按图片等静态资源忽略，无法分析的字节码显示扫描未完整。依赖/缓存目录排除策略仍存在。 |
| 提示与覆盖状态展示不一致 | 详情补上 Info 分组与零扣分说明；安装确认、详情、仪表盘和概览显示扫描不完整。未完整报告不计入安全数量。概览修正 Critical 的排序值 0 被当成空值，导致严重风险落后的问题。 |

四项核心回归（eval、文档目录脚本、shell 续行、评分持久化）在修复前均失败，修复后通过。新增回归覆盖评分策略、稳定指纹、README、二进制覆盖、下载目标正反例；既有安装闸门及危险命令回归保留。

## 能力边界与后续方向

这仍是静态启发式扫描，不是沙箱执行或完整语言解释器。当前样本结果不能外推成总体误报率、检出率或安全保证。

- 下载目标关联覆盖明确的命令参数、字面量和直接解码链；跨进程、复杂变量覆盖、函数封装、反射、动态生成的脚本仍有限制。
- 跨技能文本共现仍是零权重提示，未恢复为自动认定的数据外传。真正跨技能的数据流证明需要来源、传输介质和接收行为的关联证据。
- 文档中的危险命令示例仍可能被提示或阻断，尤其安装指令与安全教学示例混在一起时；没有全局屏蔽文档硬触发规则。
- 文件大小、数量、深度限制以及依赖/缓存目录排除仍存在。扫描未完整不等于发现恶意，也不能因高分而忽略。
- 新权重与稳定指纹在重新扫描后写入旧报告，旧数据本身不能恢复从未记录过的策略上下文。
- Windows 命令执行和 Junction 本轮未在 Windows 实机复验；此次 macOS 构建不能替代目标平台测试。

建议下一步维护版本化的正常/恶意对照语料，分别记录每类规则的精确率、召回率与耗时，再决定权重变化；不要依据单次分数高低统一调整全部规则。
